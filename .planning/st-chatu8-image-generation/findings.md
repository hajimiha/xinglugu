# 调研记录

## 已知上下文

- 当前项目已具备 SillyTavern 风格的预设、世界书、变量、正则、会话与 GAL 对话界面。
- 目标展示区域为 GAL 对话右侧“对话与行动”抽屉。
- 用户要求完整移植 st-chatu8 的提示词生成与本地/API 生图能力，不接受仅有外观的演示按钮。
- 当前工作树在本任务开始时无未提交差异；活动计划仍指向上一轮 `daylight-themes`。

- 提示词提取/整理、模板、角色外观锁定与上下文来源。
- 自动触发、手动触发、队列、进度、取消、重试与历史。
- 前端接入分支的事件协议和展示结构。
- 配置导入导出、密钥策略和本地模型的跨域要求。

## 实现约束

- IndexedDB 优先保存 Blob 与元数据，避免大图 base64 膨胀。
- 本地 `localhost`/局域网模型不能由 Vercel 服务端代请求，应由浏览器直连并给出 CORS 指引。
- 远程供应商密钥默认保存在本机，不加入 GitHub 云存档或创意工坊内容。

## 上游一手资料首轮结论

- GitHub README 明确支持 A1111/Forge Stable Diffusion、NovelAI（官方/第三方）和 ComfyUI 工作流三类核心后端。
- README 明确的完整功能不止“生成”：聊天标记触发、后端独立参数、固定正负提示词、提示词预设、动态替换、图片缓存/下载、长按改提示词、双击重绘、主题及悬浮入口。
- SD 高级项包含高清修复、面部修复、ADetailer；NovelAI 包含 SMEA、氛围参考和角色参考；ComfyUI 包含自定义 API 工作流与 LORA。
- 当前仓库设置页还出现 Banana/Grok、独立 LLM、词库、资料库、角色管理、正则、日志和发送数据等扩展页，说明最新代码能力已超过 README 的 1.0.0 摘要，需要从源码逐模块盘点。
- 两个 `my.feishu.cn` 链接被浏览器安全层拒绝直接读取；将以作者仓库、可访问镜像以及教程中可验证的公开内容交叉核对，并把不可读取项明确记录，不能凭空补造。

## 生成链路细节

- 上游不是直接把对话原文送进生图后端：先通过独立 LLM 请求把用户要求、角色预设、服装预设和可选参考图整理为绘图提示词，再从 `<images>/<image>` 或可配置开始/结束标记提取最终 prompt。
- 提示词生成前允许用户补充具体要求和多张参考图；生成后允许人工编辑并确认，说明“自动 + 可审阅”都是必要能力。
- 上游使用统一 `requestImageGeneration` 和任务管理器封装后端，再由后端生成器返回图片、变化信息、媒体类型和生成参数。
- ComfyUI 使用 `/prompt` 提交、`/history/{id}` 轮询结果、`/view` 拉取输出；需要工作流变量注入和中止能力。
- A1111/Forge 使用 `/sdapi/v1/txt2img`，并读取模型、VAE、采样器、调度器、放大器与 LORA 列表；任务可以取消。
- Banana/Grok 支持 OpenAI 风格 `/v1/images/generations`，源码还包含改图与视频分支；本项目本阶段要先完整承载图像结果，视频能力需要在统一媒体记录中保留类型而不能硬编码为图片。
- NovelAI 除直接 API 外还有作者云排队协议（加入、轮询、完成、离队）；这个第三方队列不是核心生成协议，不能作为默认或无提示依赖。
- 当前酒馆中枢采用懒加载标签页，新增“绘图”标签可保持首次游戏加载性能；右侧抽屉已是独立可滚动区域，可增加“对话/画廊”子视图。

## 本项目落点与视觉策略

- 酒馆 `TavernContext` 已集中处理会话、设置和远程 LLM，并有请求审计；生图提示词 LLM 应通过相同 API 配置与可审计编译链调用，不能另建一套隐形聊天密钥。
- 生图配置应作为 `TavernSettings.imageGeneration` 的可净化子结构；图片记录/任务因含 Blob 与生命周期，应进独立 Dexie 表，不塞进设置或会话消息。
- 酒馆中枢新增懒加载“绘图”标签；GAL 抽屉增加“对话 / 画廊”页签，默认仍打开对话，避免改变现有交互肌肉记忆。
- UI Pro Max 推荐的像素 AI 紫/粉调只用于绘图状态的局部强调；主体继续使用项目现有主题变量，确保玩家切换 UI 主题时绘图页同步变化。
- 所有表单使用受控字段；搜索/过滤用延迟值；提交通过语义化 `form`；焦点、Esc、低动态模式和 375/768/1024/1440 宽度均纳入验收。
- 当前上下文的 `sendTurn` 已有串行队列和 AbortSignal。生图需要独立于文字回合的 per-session 队列，避免图片请求阻塞玩家继续阅读或输入。

## 上游默认配置确认

- 默认后端为 ComfyUI，本地地址 `http://localhost:8188`；SD 默认 `http://localhost:7860`，并明确 `client: browser`，印证本地服务必须由玩家浏览器直连。
- 上游统一支持 prompt preset、随机预设、AI 自主分辨率、正则/词语替换档案，以及分别绑定 SD/NovelAI/ComfyUI 的活动预设。
- 默认生成控制包含：自动点击、长按编辑、点击预览、预生成、自动 LLM 生图、图像对齐/缩放、生成间隔、缓存开关与 JPEG 存储转换。
- LLM 提示词服务支持独立 API profile、请求类型 profile、按条目装配的上下文 profile，以及最近历史深度；本项目已有更完整的预设/世界书装配，因此将复用当前酒馆 API，并为绘图提示词提供专用可编辑系统模板。
- 上游 NovelAI profile 覆盖模型、采样器、调度器、scale、CFG rescale、SM/DYN、Variety/Decrisper、Vibe/Character Reference 和生成参数。
- 上游 ComfyUI profile 覆盖普通/编辑工作流、地址、模型、采样器、VAE、调度器、CLIP 和通用参数。
- 上游 OpenAI 图像兼容（Banana/Grok）还包含多轮图文 conversation preset、编辑模型、视频模型和角色参考预设；本项目的数据层会保留 `mediaType` 与参考图序列，首轮 UI 聚焦图片生成/改图，避免把视频误当图片。
- 当前项目默认世界书已经合并为单册并包含 21 个角色；绘图提示词可从当前角色、地点和会话绑定的世界书抽取，不必重新引入上游重复的角色档案系统。
