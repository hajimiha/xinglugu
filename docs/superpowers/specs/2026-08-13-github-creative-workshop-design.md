# 性撸谷 GitHub 创意工坊设计

## 目标

标题页“创意工坊”不再打开酒馆中枢，而是进入独立的联网资源市场。匿名玩家可以浏览与下载资源；完成 GitHub 登录后可以发布、更新、撤回和收藏资源。首期资源类型为世界书、预设和人物立绘组，全部沿用游戏现有 SillyTavern 数据结构并在安装前校验。

同时把用户提供的 `4718.jpg` 处理为真正带 Alpha 的奶牛娘像素立绘，替换默认 `cow-girl` 资源，不修改其角色数值或世界书设定。

## 方案选择

采用“作者公开 Gist + 公共目录 Gist 事件流”。每个资源包是作者账号下的公开 Gist；部署配置提供一个公共目录 Gist，发布、更新、撤回和收藏以结构化评论事件写入。服务端读取评论并折叠为公开目录，校验事件作者、资源所有者、资源 schema、体积和修订号。

不采用纯本地目录，因为无法跨设备共享；不采用玩家直接写主仓库或 GitHub Issues，因为会把 OAuth 权限从现有 `gist` 扩大到范围过宽的公共仓库写权限；不引入数据库，因为 GitHub 已能提供身份、可公开读取的存储、评论事件和作者所有权。

## 系统边界

### GitHub OAuth

- 继续只申请 `gist` scope。
- Access token 只保存在服务端加密 HttpOnly Cookie，浏览器 JavaScript 不可读取。
- 匿名请求只能读取公开目录、详情与包体。
- 登录请求可以创建作者公开 Gist、向目录 Gist追加事件、收藏或取消收藏。
- 服务端不保存邮箱、真实 GitHub 数字 ID、IP 画像或行为画像；前端只显示 GitHub 登录名与头像。

### 目录与资源

资源包包含：

- `schemaVersion: 1`
- `kind: lorebook | preset | portrait-pack`
- `title`：1–60 个可见字符
- `description`：10–600 个可见字符
- `version`：1–24 个可见字符
- `tags`：最多 8 个，每个 1–20 字符
- `createdAt` / `updatedAt`
- 对应类型的 `payload`

资源包不允许包含 API 密钥、接口配置、会话、聊天历史、游戏存档或全局变量。单包 UTF-8 上限 8 MiB；世界书和预设上限 2 MiB；立绘组最多 12 个角色、每个角色最多 8 个区间，并沿用现有安全图片源和好感区间校验。

目录事件包含 `publish`、`update`、`withdraw`、`favorite`、`unfavorite`。发布和更新事件的 GitHub 评论作者必须与资源 Gist owner 相同；更新和撤回必须匹配包的作者与期望修订；客户端提供的热度、作者和审核字段一律忽略。公开列表只返回当前有效且未撤回的记录。

## 前端信息架构

创意工坊作为标题页全屏工作区，保留明确的“返回标题”按钮：

1. **发现**：搜索标题、简介、作者与标签；按“近期热门、总热度、最新发布、最近更新”排序；按全部、世界书、预设、立绘组筛选。
2. **我的发布**：登录后查看自己的有效与已撤回条目，提供更新、撤回和打开 GitHub 原始资源。
3. **发布资源**：选择本地世界书、预设或一个/多个角色的立绘组，填写标题、简介、版本与标签，显示体积、内容摘要和公开发布提醒后提交。

资源卡显示类型、标题、简介、作者、版本、更新时间、收藏热度与标签。详情抽屉显示条目数量、预设提示词数量或立绘角色/槽位数量；下载按钮保存标准 JSON；“安装到本地”先显示影响预览，再执行事务。

### 安装策略

- 世界书和预设生成新的本地 UUID，并在名称后标记来源，绝不覆盖同名本地草稿。
- 立绘组按 `npcId` 匹配现有角色，预览将被更新的角色与槽位；缺失角色跳过并明确提示。
- 包校验或任一写入失败时不宣布安装成功；世界书/预设只写一个实体，立绘组先验证全部映射后再逐项保存并在失败时恢复原值。
- 下载文件不自动执行脚本、正则或网络代码，只作为现有数据结构导入。

## 视觉与响应式

沿用性撸谷现有墨绿、暖金、羊皮纸和精细像素档案语言。桌面端使用左侧分类/筛选、中央卡片目录、右侧详情或发布抽屉；手机端合并为顶部筛选条、单列卡片和全屏底部抽屉。所有按钮使用现有高级图标，不使用 emoji；触控目标至少 44px，异步操作有禁用、进度和错误状态，图片延迟加载，并支持 `prefers-reduced-motion`。

## 奶牛娘立绘

输入 JPG 的棋盘格已烘焙，图像模型编辑因安全过滤拒绝。采用本地像素分割：识别从四边连通的灰白棋盘区域，仅对该连通背景生成 Alpha，保留角色内部白色服装、丝袜高光和黑白花纹。输出替换 `public/assets/portraits/generated/cow-girl.png`，校验 RGBA、透明四角、主体覆盖和默认内容包引用。

## 错误与降级

- 未配置 OAuth：仍可匿名浏览和下载，发布区显示部署配置说明。
- 未配置目录 Gist：显示“工坊目录尚未启用”，不让界面黑屏；本地游戏与酒馆中枢不受影响。
- GitHub 限流或离线：保留上一次成功目录的内存/浏览器缓存并标记时间，不把旧结果伪装成实时。
- 资源被删除、撤回或结构损坏：详情返回稳定错误，安装按钮禁用。
- 重复提交：按钮在请求期间禁用；目录事件使用随机操作 ID 与修订冲突保护。

## 测试与验收

- 资源 schema：三种合法包、越界文本、危险图片 URL、区间重叠、超限体积和禁止字段。
- 目录折叠：作者所有权、更新修订、撤回、收藏去重、热度与时间排序。
- API：匿名列表/详情、未登录发布、Origin 拒绝、GitHub 错误归一化和配置缺失降级。
- UI：标题页打开独立工坊；搜索、类型筛选、四种排序、登录门槛、发布表单、下载、安装预览、移动端抽屉与键盘焦点。
- 资源：奶牛娘 PNG 为 RGBA、四角透明、内容包路径存在。
- 最终运行 API typecheck、全量 Vitest、生产构建、`git diff --check`，并在部署后核验标题页入口、匿名目录、GitHub 登录和至少一个测试包的发布/下载/撤回流程。
