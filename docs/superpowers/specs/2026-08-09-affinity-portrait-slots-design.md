# 好感度区间立绘槽位设计

## 目标

把每张角色卡固定的五阶段立绘改为按需扩展的好感度区间槽位。新角色默认只有一个 `0—100` 槽位；玩家拥有更多图片后，可以输入新的起止好感度创建槽位。系统自动切分旧区间，任何好感度始终只命中一张立绘。

## 方案比较

### 方案 A：连续闭区间槽位（采用）

角色卡保存按起点排序的 `{ id, minAffinity, maxAffinity, source }[]`。新增区间覆盖原有范围，被覆盖槽位自动缩短、删除或分裂。优点是完全符合玩家输入“70—100”的心智模型，能直观校验、导入导出和按数值命中；代价是需要集中式切分算法和旧数据迁移。

### 方案 B：保留五阶段并叠加自定义覆盖

继续保存五阶段图片，再增加区间覆盖表。兼容代码较少，但界面会同时存在“阶段”和“区间”两套规则，重叠优先级难以解释，也无法真正实现默认单槽。

### 方案 C：只保存区间起点

每个槽位只输入起始好感度，终点由下一项推导。数据最简，但玩家要求指定完整区间，输入 `70—100` 时界面仍需伪造终点，删除和导出也不够直观。

## 数据模型与不变量

新增 `PortraitSlot`：

```ts
interface PortraitSlot {
  id: string
  minAffinity: number
  maxAffinity: number
  source: string
}
```

`CharacterCard.portraitSlots` 成为唯一运行时真源。所有槽位满足：

- 起止值为 0—100 的整数，且 `minAffinity <= maxAffinity`；
- 按 `minAffinity` 升序排列；
- 第一个从 0 开始，最后一个到 100 结束；
- 相邻槽位首尾连续，没有重叠或空洞；
- 槽位 ID 唯一，图片来源仅允许既有的安全图片 Data URL、站内路径或 HTTPS 地址。

角色好感若暂时超过 100，立绘解析时按 100 命中；本功能不改变剧情关系阶段与既有数值成长规则。

## 新增与删除规则

新增区间视为对该范围的覆盖。例如从 `0—100` 新增 `70—100`：

- 原槽变成 `0—69`，保留原图；
- 新槽为 `70—100`，初始无图，等待上传。

若从 `0—100` 新增 `40—60`，原槽分裂为 `0—39` 与 `61—100`，两侧继承原图，新槽为空。若范围跨越多个槽位，完整覆盖的旧槽被移除，两端只保留未覆盖部分。

编辑器允许删除自定义槽位，避免误操作不可逆。删除后优先让前一槽向右扩展覆盖被删范围；删除第一个槽时让后一槽向左扩展。唯一的 `0—100` 槽不能删除。

## 旧数据迁移

旧角色卡继续允许被内容包和 IndexedDB 读取，但在仓库边界统一归一化：

- 没有旧图：生成一个空的 `0—100` 槽；
- 只有一张非空旧图：生成一个 `0—100` 槽并使用该图；
- 有多张旧图：按 `0—19`、`20—44`、`45—74`、`75—99`、`100—100` 的原阶段顺序生成槽位；缺图阶段优先沿用左侧最近的图片，左侧尚无图时使用右侧最近图片，再合并相邻同源槽，避免丢失玩家已上传图片。

保存或导出时只写新字段，不再生成五个空阶段槽。仓库默认内容版本提升，既有设备初始化时只迁移角色卡结构，不覆盖人物性格、世界书绑定或本机图片。

## 编辑器交互

角色卡编辑器的立绘区域改为：

1. 顶部显示一条 0—100 区间轨道，用分段宽度表达覆盖范围；
2. 下方显示槽位卡片，每张卡明确标注区间、当前是否有图、预览和上传按钮；
3. 默认只显示 `0—100` 一张卡；
4. 点击“新增好感区间”渐进展开起始值、结束值和确认按钮；
5. 输入无效时在字段附近显示原因，不调用浏览器原生警告；
6. 创建后自动选中新槽并把焦点移动到它的上传按钮；
7. 桌面使用双列卡片，手机改为单列，所有按钮与输入高度不低于 44px。

新增区间与图片上传都只修改角色卡草稿，仍需点击“保存角色卡”才持久化，防止误操作立即污染仓库数据。

## 游戏场景与快捷上传

场景根据当前 `Relationship.affinity` 从 Tavern 角色卡解析槽位，而不是读取静态 NPC 的阶段图片。场景快捷上传直接更新当前好感命中的槽位并持久化角色卡，刷新后仍有效；上传成功使用内部通知反馈。

角色卡列表缩略图优先显示 `0` 好感命中的图片，若为空则显示第一个有图片的槽位，最后回退姓名首字。

## 校验、错误与发布

- 区间算法只接受整数和 0—100；错误消息明确说明修正方式。
- 内容包拒绝畸形、重叠、留空洞或不安全图片来源的槽位。
- 单图不设容量上限，继续保留 12 MB 整包发布预算。
- 旧内容包可以导入并被归一化；新内容包只输出区间槽位。

## 测试与验收

- 纯函数：默认槽、前后裁剪、中段分裂、跨槽覆盖、删除回填、边界命中、非法范围。
- 迁移：空五阶段、单图、多图、已是新结构、恶意重叠内容包。
- 组件：默认仅一槽；输入 70—100 后显示 0—69 与 70—100；新槽上传；错误就地显示；保存后重载仍存在。
- 场景：不同好感度命中对应槽，快捷上传写回 Tavern 角色卡。
- 响应式：1440×1000、390×844，检查滚动、触控目标、重复 ID、横向溢出和控制台错误。

## 非目标

- 不改变 NPC 好感获取速度、剧情五阶段或礼物规则；
- 不提供图片裁切、压缩和云端素材库；
- 不修改世界书对关系阶段的叙事规则。
