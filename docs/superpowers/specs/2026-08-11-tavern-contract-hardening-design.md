# 酒馆契约加固设计

## 目标

在不重写现有 React、Dexie 与浏览器直连 LLM 架构的前提下，修复 TavernWeave 审计确认的提供商协议、会话资源、变量、SillyTavern 导入导出与游戏精力事务问题，并保留现有存档、预设、世界书、角色立绘和会话。

## 方案选择

1. **局部边界加固（采用）**：在请求适配、资源解析、变量提交、兼容导入和对话提交五个边界建立单一契约。改动可分阶段验证、可回滚，不改变数据库主表和 UI 信息架构。
2. **重写酒馆运行时（拒绝）**：可以统一所有协议，但会扩大到提示词编译、仓储和 UI，现阶段风险与验证成本过高。
3. **只增加警告（拒绝）**：无法阻止 Cohere 400、变量污染、错误显示正则与零精力远程请求，不能满足修复要求。

## 行为契约

### 提供商请求

- OpenAI 兼容协议继续保留完整消息顺序。
- Anthropic、Gemini 与 Cohere 遇到“非 system 消息之后再次出现 system”时必须在浏览器发出任何网络请求前返回中文可行动错误，禁止静默重排。
- Cohere 只接受 `0—1` 的温度、频率惩罚与存在惩罚；两种惩罚不能同时为非零。为零的惩罚字段不发送。
- API 设置页使用与真实请求相同的提供商能力校验。

### 会话资源

- 会话的有效预设由 `presetBinding`、当前设置和可用预设共同决定。
- 请求、输出正则、显示正则、世界书挂载状态和请求检查器读取同一解析结果。
- 固定预设被删除后，会话明确退回“跟随活动预设”，不保留伪固定状态。

### 变量事务

- 模型 `<vars>` 只能更新已声明且可写的全局或会话变量。
- 更新值按定义类型转换并执行 min/max；无法转换、未知键和只读游戏镜像不会写入，并产生请求诊断。
- 全局变量写回 `TavernSettings.globalVariables`，会话变量写回 `ChatSession.variableDefinitions/variables`；不得用会话影子覆盖全局定义。
- 提示词宏产生的临时变量只在当前请求装配中生效，除非存在相应可写定义。

### SillyTavern 兼容数据

- 世界书条目保留原始 UID、未知字段与整册未知设置；编辑已支持字段时只覆盖对应字段。
- 正则保留原始 dialect 字段和三态布尔；`promptOnly` 与 `markdownOnly` 同时为 true 时拒绝导入。
- 当前运行时未实现的世界书字段或注入位置在导入成功提示与请求诊断中明确列出，不再伪称完整兼容。

### 游戏事务与内容所有权

- 每次 NPC 模型回合开始前必须有至少 1 点精力；无精力时不得发送网络请求或持久化消息。
- 每次成功提交一个模型回合消耗 1 点精力并执行一次关系结算，不再按“打开一次窗口”计费。
- 角色卡只提供身份、首句和立绘；人物描述、性格、场景与示例不再进入模型提示词，世界书是人物文字设定唯一来源。
- 仓库内容包加载失败必须返回结构化原因并在酒馆中枢可见，不能静默伪装为正常默认内容。

## 数据兼容

给 `LorebookEntry` 与 `TavernRegexScript` 增加可选的原始兼容元数据，只扩展 IndexedDB 对象，不改表结构。旧记录没有元数据时继续按当前导出格式工作；新导入记录可无损往返。现有游戏存档和酒馆内容不删除、不重置。

## 验证

- 每项生产修改先有可观察的失败测试。
- 定向测试覆盖提供商请求体、固定预设显示、变量事务、导入导出往返、零精力和多轮结算。
- 完成全量 Vitest、TypeScript/Vite 构建、`git diff --check`、TavernWeave 安全/性能扫描。
- 使用 Edge 在 1440×900 与 390×844 检查酒馆八标签、NPC 对话、滚动、关闭、控制台与横向溢出。

## 范围外

- 不接入后端代理，不更换数据库，不升级依赖。
- 不伪造模型隐藏思维，不新增 SillyTavern 宿主扩展 API。
- 不实现尚未承诺的完整 SillyTavern 宿主运行时；未支持语义必须显式报告。
