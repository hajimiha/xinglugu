# 村庄开场 GAL 导览设计

## 背景

当前新游戏流程为标题页进入游戏、显示 `PlayerNameGate`、确认玩家姓名后立即进入普通村庄界面。项目已经具备全屏 GAL 对话、角色立绘、村庄地图、响应式地图热点和本地/云端存档能力，但还没有连接姓名确认与正式游戏之间的开场剧情。

本功能在新玩家确认姓名后插入一段由村长洛岚主持的全屏 GAL 导览。村庄地图作为连续背景，洛岚依次介绍全部 11 个现有地点；每个地点的对白出现时，地图平滑缩放并将该地点移动到镜头中心。剧情结束或玩家主动跳过后才进入普通游戏。

## 目标

- 新档确认玩家姓名后自动进入开场剧情，不需要额外入口。
- 使用项目现有 GAL 视觉语言：全屏舞台、人物立绘、说话者名牌、底部文本框和推进控制。
- 使用村长洛岚的现有角色设定和立绘欢迎玩家。
- 依次介绍当前地图中的全部 11 个地点，每处介绍都有明确且准确的地图聚焦镜头。
- 右上角常驻“跳过剧情”按钮，支持安全确认和键盘操作。
- 自然结束与跳过都可靠持久化，完成后不再自动重播。
- 已经取名的旧存档升级后不补播，避免打断现有进度。
- 保持普通地图、角色对话、农场、战斗、商店、存档和其他功能行为不变。

## 非目标

- 不调用 LLM 动态生成开场台词。
- 不提供剧情选择分支、自动播放、快进、回看日志或语音。
- 不记录逐句播放进度；播放中刷新页面会从开头重新开始。
- 不新增地图地点、角色、任务、奖励或时间消耗。
- 不在本轮增加设置页中的开场重播入口。
- 不重构普通 `VillageMap` 的旅行、拖动或选中逻辑。

## 推荐架构

采用独立的 `VillageOpeningIntro` 全屏导演组件，而不是给普通 `VillageMap` 增加剧情模式。

组件在 `AppContent` 中由持久化状态控制：

1. 姓名尚未确认时，保持现有姓名门禁流程。
2. 姓名已确认且开场未完成时，只渲染全屏开场导演层，不挂载普通 HUD、地图和游戏交互区。
3. 开场已完成时，渲染现有普通游戏界面。

这种边界保证剧情期间不会触发地图点击、旅行、快捷键、弹窗或时间推进，也避免给现有地图组件增加只服务于一次性剧情的状态分支。

开场功能拆分为四个稳定边界：

- `opening-story`：只读、版本化的剧情节拍数据。
- `opening-camera`：根据视口、地图宽高比和地点矩形计算镜头变换的纯函数。
- `VillageOpeningIntro`：维护当前节拍、跳过确认、键盘推进和画面渲染。
- 游戏状态与存档：只负责“开场是否完成”，不保存表现层的临时节拍。

## 剧情数据契约

每个剧情节拍使用显式数据结构，至少包含：

```ts
interface VillageOpeningBeat {
  id: string
  speaker: 'narrator' | 'loran'
  text: string
  focusLocationId?: LocationId
  camera: 'overview' | 'location'
}
```

对白文本支持安全的玩家姓名占位符，由 React 文本节点插入，不使用 `innerHTML`。地点名称与镜头目标使用 `LocationId` 关联现有 `locations` 数据，禁止维护第二套百分比坐标。

开发期增加完整性断言或测试：

- 节拍 ID 唯一。
- 所有 `focusLocationId` 都能在 `locations` 中找到。
- 11 个地点各出现一次且只出现一次。
- 第一和最后一个镜头均为村庄全景。

## 剧情脚本与路线

剧情采用约 15 个节拍，正常阅读时长约 2–3 分钟。最终文案在保持以下含义的前提下可做小幅润色：

1. **村庄全景·旁白**：清晨雾色散开，性撸谷的道路与屋顶映入眼帘。
2. **村庄全景·洛岚**：“你就是 `{玩家姓名}` 吧？欢迎来到性撸谷。我是这里的村长洛岚。正式开始生活前，让我带你认一认今后常走的路。”
3. **苔灯农场**：“先从脚下这片苔灯农场开始。这里是你的新家，也是播下第一粒种子、建立自己生活的地方。”
4. **魔女之家**：“西边林荫下是魔女之家。需要恢复药水、永久药剂或五行战斗道具时，可以去找黛芙。”
5. **杂货店**：“风铃响着的地方是杂货店。种子和常用材料能在那里买到，收获的农产品也可以交给柳安处理。”
6. **图书馆**：“图书馆保存着村庄旧档与各类知识。若对这里的历史或某件事感到疑惑，书架往往会给你答案。”
7. **医院**：“这是医院。受伤或身体不舒服时别硬撑，维娜和苏槿会照顾好你。”
8. **渔家**：“东南岸边住着渔家。想了解潮汐、鱼群和钓鱼技巧，就去听听潮音与汐夜的经验。”
9. **魔物娘商店**：“林下共生所也叫魔物娘商店。塞拉她们会帮助你认识共生伙伴、牧场经营和合适的饲料。”
10. **铁匠铺**：“羽火升起的屋子是铁匠铺。工具升级、矿石精炼和装备修理，都少不了岩雀的手艺。”
11. **村长家**：“这里是村长家，也是壁炉议事厅。村民委托、季节会议和需要我协助的村务，都可以来这里谈。”
12. **猎人帐篷**：“北林边缘是猎人帐篷。准备进入危险区域前，先向凛学习战斗和野外生存，会让旅途安全许多。”
13. **矿洞**：“最后是矿洞。地下埋着珍贵矿石，也藏着真正的危险；带齐工具和补给，再决定走多深。”
14. **村庄全景·洛岚**：“路一开始总显得很多，但你很快会找到自己的节奏。这里的人，也会慢慢记住你的名字。”
15. **村庄全景·洛岚**：“那么，去看看属于你的性撸谷吧，`{玩家姓名}`。愿你的第一天，从一件真心想做的事开始。”

路线使用空间上相对连续的蛇形移动，减少无意义的大幅折返；剧情结尾必须缩回全景，给玩家清晰的“导览完成”视觉信号。

## GAL 界面与交互

### 舞台层级

从后到前依次为：

1. 填满视口的低对比度模糊地图底图，避免竖屏下出现空白边缘。
2. 保持原始宽高比的清晰地图相机层，负责缩放和平移。
3. 轻微暗角与底部渐变遮罩，确保立绘和文字可读。
4. 洛岚全身立绘；旁白节拍时轻微降低亮度，洛岚发言时恢复明亮。
5. 底部 GAL 文本框与说话者名牌。
6. 右上角“跳过剧情”按钮和跳过确认层。

复用现有颜色、圆角、阴影、字体、按钮和 GAL 视觉变量，但使用独立的 `village-intro-*` 类名，避免开场样式与 `TavernDialogue` DOM 结构互相依赖。

### 推进方式

- 点击文本框空白区域或“继续”按钮进入下一节拍。
- `Enter`、`Space` 和 `ArrowRight` 可推进。
- 输入焦点位于跳过确认对话框时，不响应剧情推进快捷键。
- 第一节拍显示“开始”，中间显示“继续”，最后显示“进入性撸谷”。
- 屏幕显示 `当前节拍 / 总节拍`，让玩家感知剧情长度。
- 不自动推进，避免阅读速度差异造成漏读。
- 连续快速点击只依据当前节拍索引计算最终状态，不排队执行异步动画。

### 跳过剧情

- 右上角按钮始终可见，文案为“跳过剧情”。
- 点击后打开轻量确认框：“确定跳过村庄介绍吗？之后将直接进入游戏。”
- 确认框提供“继续观看”和“确认跳过”；默认焦点落在“继续观看”。
- `Escape` 关闭确认框并回到剧情；确认跳过后焦点无需归还，因为开场组件随即卸载。
- 跳过、自然结束和重复触发统一调用同一个幂等完成动作；一旦完成，不允许后续动画回调覆盖状态。

## 地图相机

### 基础布局

地图原始宽高比为 `1672 / 941`。清晰地图层以 `contain` 方式计算基础尺寸，保证全景镜头能看到完整地图；视口剩余区域由同图的模糊、放大底层填充。这样在手机竖屏中既不裁掉全景，也不会出现突兀空白。

### 地点聚焦算法

纯函数输入：

- 视口宽高；
- 地图宽高比；
- 地点的百分比矩形；
- 响应式安全区和最大/最小缩放范围。

计算过程：

1. 求出 `contain` 后地图在视口内的基础尺寸与居中原点。
2. 将地点矩形中心转换为基础地图像素坐标。
3. 根据地点矩形尺寸与目标安全区计算合适缩放，使地点保留上下文而不是占满整个屏幕。
4. 把地点中心移动到可用舞台的视觉中心；桌面端为文本框和洛岚立绘预留偏移，移动端以地图中央偏上为目标。
5. 对 X/Y 平移做边界夹取，避免清晰地图层在放大后暴露超出允许范围的边缘。
6. 输出有限的 `scale`、`translateX`、`translateY`；任何无效输入都安全回退全景。

建议缩放范围：桌面约 `1.35–2.35`，手机约 `1.2–1.85`。实际常量以 375、768、1024、1440 四档视觉验收结果为准，但算法和测试不依赖某个固定屏幕。

节拍改变时使用单一 CSS `transform` 过渡；新的节拍会直接替换目标变换，不创建动画队列。常规运动时长约 650–900ms，使用柔和缓动。启用 `prefers-reduced-motion: reduce` 时取消平移缩放动画，只做不超过约 120ms 的淡入变化。

## 角色立绘

导览角色固定为洛岚（`loran`）。优先复用项目现有角色卡立绘解析结果，使玩家自定义立绘在可用时也能显示；读取失败或角色库尚未完成初始化时回退到项目内置资源 `./assets/portraits/generated/loran.png`。图片缺失时使用带“洛岚”文字的风格化占位，不让剧情因为资源错误而阻塞。

桌面端洛岚位于舞台侧边并避开当前地图聚焦点的核心区域；移动端缩小立绘并降低到底部文本框后方，确保地图地点和对白仍是主要信息。旁白节拍立绘轻微变暗，洛岚节拍恢复明亮，延续现有 GAL 的说话者视觉反馈。

## 状态、存档与迁移

`PlayerProfile` 增加显式布尔状态，例如：

```ts
hasCompletedVillageIntro: boolean
```

状态规则：

- 全新默认玩家资料：`false`。
- `SET_PLAYER_NAME`：只确认姓名，不提前完成开场。
- `COMPLETE_VILLAGE_INTRO`：幂等地设为 `true`。
- 自然结束和跳过均派发该动作。
- 已为 `true` 时重复派发不得修改其他游戏状态。

存档格式进行显式版本迁移：

- 新格式保存完整布尔字段。
- 旧存档没有该字段且 `hasConfirmedName === true`：迁移为 `true`，不补播。
- 旧存档没有该字段且姓名未确认：迁移为 `false`，确认姓名后正常播放。
- 畸形非布尔值按上述旧档规则清洗，而不是使用 JavaScript 真值转换。

只保存完成状态，不保存当前节拍。播放中刷新会重新从全景开幕开始；这避免半完成脚本在将来剧情版本变化后指向错误节拍。

## 响应式与可访问性

- 覆盖 375、768、1024、1440 像素宽度，不产生页面横向滚动。
- 文本框在手机上限制高度并允许文本区域内部滚动，控制按钮保持可见。
- 所有按钮触控区域至少 44×44 像素。
- 文本框使用明确的说话者标签；旁白不伪装成洛岚发言。
- 地点切换时使用 `aria-live="polite"` 播报“正在介绍：地点名”，但不重复朗读整段正文。
- 跳过确认层使用真正的对话框语义、焦点圈定和焦点恢复。
- 键盘焦点样式清晰；图标按钮均有可读名称。
- 亮暗、缩放和位置不是唯一信息来源，地点名和说话者名始终以文字呈现。
- `prefers-reduced-motion` 下取消大幅镜头运动和立绘位移。

## 错误处理与边界

- 地点 ID 不存在：记录开发错误并回退全景，剧情仍可继续与跳过。
- 视口宽高为零或计算结果非有限数：回退全景变换。
- 立绘加载失败：显示姓名占位，不阻塞推进。
- 快速重复推进：节拍索引限制在合法范围，完成动作最多生效一次。
- 跳过确认期间：地图动画可完成，但剧情节拍不推进。
- 存档写入由现有 GameProvider 持久化链路处理；组件先完成内存状态切换，现有存档错误机制负责报告写入异常。
- 浏览器后退、页面隐藏或旋转屏幕：根据当前节拍和新视口重新计算镜头，不改变节拍。
- React Strict Mode 重复执行：完成动作保持幂等，不创建计时器依赖或重复副作用。

## 测试与验收

### 纯函数测试

- 11 个地点覆盖完整、无重复、无未知 ID。
- 全景变换为有限值且居中。
- 中央、四边和四角地点在桌面与手机视口下都保持有限变换并通过边界夹取。
- 零尺寸、异常矩形和极端宽高比安全回退。
- reduced-motion 模式不依赖动画完成事件才能推进。

### 状态与存档测试

- 新档姓名确认后仍为未完成，触发开场。
- 完成动作只修改开场完成状态且可重复调用。
- 已确认姓名的旧存档迁移为已完成。
- 未确认姓名的旧存档迁移为未完成。
- 新格式存档往返保持字段。

### 组件测试

- 姓名确认后开场自动出现，欢迎台词包含安全显示的玩家姓名。
- 初始与最终节拍为全景。
- 推进每个地点时地点名称、镜头目标和节拍计数一致。
- 鼠标与键盘推进均生效，确认框打开时推进键无效。
- 点击跳过先出现确认；取消继续观看；确认后开场消失并进入正常游戏。
- 自然播放到末尾后进入正常游戏，刷新不重播。
- 立绘加载失败时占位可见且仍可完成剧情。

### 回归与视觉验证

- 运行相关定向测试、完整测试套件、TypeScript 检查和生产构建。
- 使用真实浏览器在 375、768、1024、1440 视口逐段检查所有镜头，确认地点位于视觉中心、文本可读、按钮不遮挡、无横向滚动。
- 检查 reduced-motion、键盘全流程、跳过焦点管理和刷新后的完成状态。
- 完成后复测现有姓名门禁、普通村庄地图、单/多角色 GAL 对话和存档加载，确保无行为回归。

## 发布与回滚

实现只涉及开场剧情数据、相机纯函数、开场组件、玩家资料字段、存档迁移、入口编排、独立样式及其测试。

发布前按既定授权：先为当前 `main` 建立可恢复的本地备份引用或补丁，再提交经过完整验证的新版本并推送到远端 `main`。不使用强制推送，不清理用户未跟踪文件。若线上出现阻断问题，可从备份引用恢复发布前版本。

## 设计自审

- **需求完整性：通过。** 自动进入、GAL 表现、村庄地图、逐地点缩放居中、洛岚导览、全部 11 地点、右上角跳过均有明确实现边界。
- **兼容性：通过。** 旧的已命名存档不会被强制补播；新档流程不会提前标记完成。
- **状态安全：通过。** 只有一个持久化完成位，跳过与自然结束汇入幂等动作；无动画回调决定业务状态。
- **地图一致性：通过。** 镜头复用 `locations.mapPosition`，没有第二套坐标源。
- **回归隔离：通过。** 普通 `VillageMap` 和 Tavern 对话不承担开场状态，剧情期间普通交互不挂载。
- **响应式与无障碍：通过。** 明确规定四档视口、减少动态效果、键盘、焦点、触控尺寸和文本替代。
- **失败恢复：通过。** 地点、视口或立绘异常都能回退且不阻塞跳过/完成。
- **范围控制：通过。** 不扩展到重播、语音、剧情分支、奖励或其他玩法。
